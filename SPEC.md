# Специфікація: Resume Parser v0

## 1. Мета
Інструмент командного рядка, який приймає папку резюме (PDF/DOCX) і одну вакансію,
для кожного резюме будує структурований JSON-профіль, оцінює відповідність вакансії
(0–100 балів з поясненням) і формує підсумковий CSV-рейтинг кандидатів.

## 2. Вхідні дані
- **Папка резюме**: `resumes/*.pdf`, `resumes/*.docx` (10 файлів для тесту).
- **Вакансія**: один текстовий/JSON-файл `vacancy.json` з полями:
  `title`, `must_have_skills[]`, `nice_to_have_skills[]`, `min_years_experience`, `description`.

## 3. Вихідні дані
- **JSON-профіль** на кожне резюме (`out/profiles/<filename>.json`), фіксована схема:
  ```json
  {
    "name": "string",
    "contacts": {"email": "string|null", "phone": "string|null"},
    "years_experience": "number|null",
    "skills": ["string"],
    "education": [{"degree": "string", "institution": "string", "year": "string|null"}],
    "work_history": [{"company": "string", "title": "string", "period": "string", "description": "string"}],
    "raw_text_excerpt": "string (перші 500 символів — для дебагу)"
  }
  ```
- **Оцінка + пояснення** на кожне резюме (`out/scores/<filename>.json`):
  `{"score": 0-100, "matched_must_have": [...], "missing_must_have": [...], "matched_nice_to_have": [...], "explanation": "string"}`.
- **Підсумковий CSV** (`out/ranking.csv`): `filename, name, score, top_reason`, відсортований за `score` (desc).

## 4. Кроки обробки (пайплайн)
1. **Читання файлів** з папки резюме (перевірка розширення, пропуск непідтримуваних).
2. **Витяг тексту**: PDF → `pdfplumber`, DOCX → `python-docx`. Якщо текстовий шар порожній
   (скан без OCR) — файл позначається як `extraction_failed` і пропускається з логом.
3. **Структуризація через LLM** (Claude API): текст резюме → фіксований промпт → JSON-профіль
   за схемою з п.3. Валідація JSON (парситься, обов'язкові поля не null для `name`).
4. **Порівняння з вакансією через LLM**: профіль + вакансія → оцінка 0–100 і пояснення
   одним викликом (щоб оцінка та пояснення були узгоджені).
5. **Запис проміжних артефактів**: JSON-профіль і JSON-оцінка на диск (для дебагу і повторного
   тест-прогону без повторних викликів LLM).
6. **Агрегація в CSV**: збір усіх оцінок, сортування за `score` desc, запис `ranking.csv`.

## 5. Формула оцінки (керівні принципи для промпту)
- Обов'язкові навички (`must_have_skills`) — основна вага; кожна відсутня навичка суттєво
  знижує бал.
- Досвід: менше за `min_years_experience` — штраф пропорційно нестачі.
- Бажані навички (`nice_to_have_skills`) — бонус, не критичний.
- Пояснення має явно називати, які навички збіглися/не збіглися і чому дано саме такий бал —
  це дозволяє ручну перевірку адекватності без повторного читання резюме.

## 6. Як перевіряємо результат
- **Тестовий набір**: 10 синтетичних резюме, написаних так, щоб очікуваний ранг був відомий
  наперед (напр. 3 сильних збіги, 4 середніх, 3 явно нерелевантних).
- **Ручна перевірка**: чи топ-3 і низ-3 у `ranking.csv` збігаються з очікуванням; чи пояснення
  логічно узгоджене з балом (високий бал без згаданих must-have навичок = помилка).
- **Edge cases**: порожнє/майже порожнє резюме, резюме без жодної релевантної навички,
  пошкоджений/захищений паролем PDF, резюме іншою мовою, дублікат файлу.
- Результати ручної перевірки і типові помилки LLM фіксуються в `RETRO.md` (крок 3 завдання).

## 7. Технології
- Python 3.11+, `pdfplumber`, `python-docx`, `anthropic` (Claude API), `pandas` або стандартний `csv`.
- Конфігурація через `.env` (`ANTHROPIC_API_KEY`) — не комітиться в репозиторій.

## 8. Обмеження v0 (поза скоупом)
- Без OCR для сканованих PDF без текстового шару.
- Одна вакансія на прогін (без пакетного порівняння з кількома вакансіями одночасно).
- Без веб-інтерфейсу — тільки CLI.
- Без збереження результатів у БД — тільки файли на диску.
